Project Background

Problem Statement & Motivation

Bridging the gap between raw transactional data and actionable business insights.

⚠️ Industry Challenges
  • Data Fragmentation: Transaction records, customer interactions, and inventory quantities often exist in isolated silos.
  • Lagging Reporting: Traditional batch reporting takes hours or days to generate, missing critical market trends.
  • Stockouts & Revenue Loss: Lack of real-time low-stock alerts leads to missed sales opportunities and poor fulfillment.
  • Insecure Database Access: Exposing databases directly to web clients introduces critical data leakage vulnerabilities.
💡 Proposed Solution: ShopPulse BI
  • Unified Executive Dashboard: Aggregates Gross Sales, Order Velocity, Customer Growth, and Catalog Health into 4 instant KPIs.
  • Interactive Visual Analytics: Dynamic Recharts graphs for monthly revenue trajectory and weekly order state distributions.
  • Direct Inventory CRUD: Real-time product & category management with referential constraints.
  • PostgreSQL Row Level Security: Enterprise security policies enforcing strict role-based data protection.

Database Engineering

PostgreSQL Schema & Relational Design

Normalized 3NF schema with foreign key integrity, non-negative checks, and indexes.

1. profiles & customers
• profiles: id (UUID PK -> auth.users), full_name, role.
• customers: id (UUID PK), full_name, email (UNIQUE), created_at.
User Entities
2. categories & products
• categories: id (BIGINT PK), name (UNIQUE), description.
• products: id (PK), name, category_id (FK), price (CHECK >= 0), stock_quantity (CHECK >= 0).
Catalog Taxonomy
3. orders & order_items
• orders: id (PK), customer_id (FK), order_date, status, total_amount.
• order_items: id (PK), order_id (FK CASCADE), product_id (FK), quantity, unit_price.
Transactional Ledgers
⚡ B-Tree Performance Indexes Implemented
CREATE INDEX idx_products_category ON products(category_id); • CREATE INDEX idx_orders_customer ON orders(customer_id); • CREATE INDEX idx_orders_date ON orders(order_date); • CREATE INDEX idx_order_items_order ON order_items(order_id);

Enterprise Security

Row Level Security (RLS) & Auth

Granular database-level access control preventing unauthorized data leakage.

🔒 Why Row Level Security (RLS)?

Traditional apps rely solely on frontend hiding of buttons. If an attacker queries the API directly, hidden buttons offer zero protection.

PostgreSQL RLS ensures the database engine itself rejects unauthorized queries even if the frontend code is compromised.

📜 PostgreSQL Security Policies
  • Public Read: Categories and Products are publicly readable for storefront browsing.
  • Authenticated Write: Only authenticated admin accounts can mutate products or categories.
  • Private Ledgers: Customer profiles and orders require authenticated tokens.
🔑 Seamless Authentication Architecture
Supports standard Supabase JWT authentication as well as an instant evaluator sign-in mode for effortless college viva demonstrations.
